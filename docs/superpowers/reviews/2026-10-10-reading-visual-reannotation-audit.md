## Confirmed missing behavior

1. **No saved-source retry endpoint/service or UI action.** Worker routes offer snapshot, stream, cancel only (`src/worker/index.js:220-222`; `functions/api/reading-visual-job.js:14-89`). Existing cloud polling excludes failed/error/expired/cancelled and requires `entry.visual`; local subscription requires a valid resume. Neither path initiates re-annotation.
2. **No durable failed-attachment state or fallback snapshot.** `functions/lib/journalEntries.js:93-115,246-269` drops attachment failure reasons and returns visual data only when linked. Its journal INSERT (`:156-211`) stores neither `readingResultId`, requested binding, fallback visual snapshot, nor retry state. Migration `0036_reading_visual_results.sql:5-42` has only registered results and successful links. A client may briefly retain the submitted snapshot (`useJournal.js:496-503`), but a successful cloud reload replaces it with the API list (`:202-223`), which only joins successful links. Therefore failed attachment is not durably discoverable/retryable and its local fallback can disappear on reload.
3. **Existing transport retries do not supply the missing workflow.** `src/lib/readingVisualStream.js:23-28,31-94` has six consecutive unsuccessful connections by default, exponential delay capped at 10 seconds, EOF cumulative-snapshot recovery, and immediate terminal 401/403/410. This reconnects an existing job; it does not bound or authorize new inference attempts. Cloud polling has no attempt cap and never submits inference.
4. **Expired lifecycle cannot be reopened with ordinary init.** Visual DO TTL is 24 hours (`src/worker/readingVisualJob.js:16,187-193`); private storage defaults to one hour when no explicit expiry is supplied (`readingVisualStorage.js:27`). Alarm/access expiry invalidates requests, clears private state and returns 410 (`readingVisualJob.js:126-159,491-517`). `/init` explicitly rejects expired/revoked state (`:177-186`). A failed, still-live job can accept a fresh trusted observation of the same unprocessed raw; successful already-analyzed raw skips new inference (`:198-239,257-290`). No saved-journal caller currently provides that observation.

## Canonical-source and access distinction

**Cloud:** obtain `journal_entries` by authenticated owner and entry ID; reconstruct exact `narrative`, ordered cards/positions/orientations, deck, question, and reflections from that row. Compute raw/spread/context hashes server-side with `shared/reading/visualSourceIdentity.js:6-41`; require the exact stored source, edition/catalog, and existing link/revision. Retry bodies cannot supply replacement raw, owner, or a claimed result binding. First retry a valid same-owner existing attachment without inference. A mismatched/foreign claimed result must never be attached; any newly authorized annotation must operate on the owner's own saved row. A linked expiry retains static D1 state, enabling owner-proven recovery (`readingVisualResults.js:227-244`).

**Guest/local, including signed-in users without cloud entitlement:** preserve `personalReading` as exact original raw Markdown, ordered cards/positions/orientations, deck, question/reflections, and public binding/cached cues together in the scoped existing entry. `useSaveReading.js:80-105` currently chooses raw then normalized fallback; normalized-only historical entries cannot prove the original raw identity and must be treated as a separately submitted saved source, never as authorization to mutate the old job. Recompute the complete fingerprint from the saved fields. Preserve cached cues during retry/failure. Store fresh resume/replay credentials and retry bookkeeping separately under `visualStorageNamespace`; exclude capabilities from entry/export/share/DOM events. An expired opaque result ID and client snapshot cannot authorize access/reset of old private work. Guest retry may authorize fresh bounded annotation of the submitted exact prose, with fresh server-issued replay identity/capability and no lookup of old private results.

**Pending identity seam:** the spec keeps narrative `readingResultId`/gesture run ID stable and separates transport IDs (`handoff:39`), while the current visual DO is addressed directly by that ID. A replay attempt/transport identity or trusted restart epoch is required. Preserve the narrative identity and saved source; do not silently generate another narrative identity to solve expiry, reopen public init, trust a caller-supplied original ID, or resurrect a revoked/deleted result. Cloud restart can be authorized by existing owned journal rows; local replay requires fresh source authorization. This design is not implemented yet.

## Smallest safe bounded policy (recommendation, pending)

- Add one explicit **Retry visual accompaniment** submission per saved full source fingerprint; no inference on mount, reload, poll, or readiness lookup. Valid pending work resumes normally. Complete validated cues remain readable without provider readiness. Explicit cancellation/revocation/deletion is not expiry and is not automatically eligible.
- Persist/atomically claim the retry before dispatch; concurrent clicks/tabs/reloads return the same attempt, binding, status and fresh private resume handle instead of starting another call. Scope cloud claims to owner + entry + fingerprint; local claims need server-enforced anonymous admission/idempotency as well as browser-scoped bookkeeping. Browser state alone cannot enforce an inference budget, and server namespaces must not trust local namespace strings as ownership.
- Configuration/readiness/offline failures before dispatch preserve source/cues and do not consume an inference attempt. Once dispatched, timeout/malformed/rejected response counts as the one attempt; stop with a recoverable status instead of an automatic retry loop. Keep existing transport retry budget separate. Use the configured independent adapter timeout (30 seconds default, 60 seconds cap) and cancellation.
- For a linked failed job, reuse trusted prior ledger/request semantics; do not clear accepted cues. For expiry or absent registration, create an authorized replay attempt with a fresh capability while preserving cached cues until a validated successor snapshot is available. Link/rebind only by conditional source/owner/attempt checks; duplicate attempts cannot replace a later binding.
- Recheck existence/owner/fingerprint at admission and commit. Deletion/account switch while admission, initialization, inference, or hashing is pending must abort/reject and leave no resurrected entry/result. Exhausted attempt remains discoverable after reload; a new local entry ID/result transport ID must not reset the budget for the same saved source.
