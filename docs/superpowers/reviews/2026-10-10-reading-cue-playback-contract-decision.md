# Playback contract decision and bounded visibility repair

Status: selection policy decided by the user on 2026-10-10 — **skipped highlights are not acceptable**. The latest-visible rule is replaced by visible turn-taking. Task 3 acceptance still requires the strict paced browser gates on the changed revision; this document records the decision and contract, not qualification.

## Decision

The earlier renderer kept only the latest visible candidate and marked every earlier visible candidate as consumed before deciding whether the active cue blocked adoption. Task 2 reproduced the effect: timely Star pool, memory and ground cues, and 15 five-card cues including every identity introduction and the Ace/Queen pair, were consumed without ever being shown. When asked to choose a playback policy, the user answered that skipped highlights are not acceptable.

## Contract after the decision

- **Every visible connection gets a turn.** In a live reading, each fully rendered, still-visible connection that has not yet played takes its own turn in source order. A turn lasts the existing full active phase (`ACTIVE_MS = 1800`). Later visible connections wait; nothing visible is consumed unseen.
- **Selection is still derived, not queued.** The next turn is recomputed from the current visibility set at each event. No stored playback queue exists, and the reducer exposes only the next waiting connection as `pending`.
- **No captured backlog.** A connection whose passage is passed above the viewport is consumed without a later replay. A waiting connection that leaves view below the viewport is not consumed; it takes its turn when it becomes visible again. A turn ends with its own passage: if the current passage leaves view, the next visible connection plays at once, and the interrupted connection is not replayed later.
- **Explicit inspection wins.** Holding a phrase or card replaces the current automatic turn; release resumes the earliest unplayed visible connection, and the held deadline and identity are unchanged. A card modal, card-detail inspection, keyboard focus inside the companion stage (focus that matches `:focus-visible`), or a hidden document suspends the running turn instead: no new connection is adopted, motion stops, and the remaining turn time resumes when the inspection or pause ends, so a connection is not lost behind it. Pointer focus is not an inspection: a clicked or tapped stage button keeps focus without a keyboard ring, and suspending there would let unseen connections scroll away. Whether a screen reader's cursor moves DOM focus at all is unverified and belongs to the VoiceOver checklist. A status change that arrives with a source update suspends or resumes the turn the same way as a separate status event, and a new turn never inherits a suspension.
- **Reduced motion takes the same turns without motion.** The same connections appear in the same order as static meaning: phase `static`, no motion deadline (`activeUntil = 0`), no animation. A separate turn deadline (`turnUntil`) only ends the static turn when another visible connection is waiting. Switching motion preference mid-turn keeps the current connection for the rest of its turn without restarting motion.
- **Restored readings are unchanged.** A restored or reannotated reading has no arrival sequence: static meaning follows the newest visible passage, there are no turn or motion deadlines, and every connection remains available by explicit revisit.
- **Unchanged elsewhere.** One annotation request in flight with one latest pending source snapshot, accepted cues surviving ledger coalescing, no forced scroll, unchanged prose and reader pacing (25 words/second delivery, 180 words/minute independent reader), the 600 ms minimum exposure and every scoring threshold.

The turn length was not shortened to make a queue drain faster: the authored finite traces (1800 ms) and water settlement (1500 ms) keep their full duration.

## Bounded visibility repair (unchanged, and the rule this revision keeps)

The narrow renderer defect was reproduced independently before application edits using the exact delivered Queen cup source quote. In a 1000 px viewport, the interactive span's bounding rectangle began at 992.73 px while its two source text Range rectangles began at 1002.73 and 1038.73 px. The runtime reported that cue visible despite both source lines being below the viewport. The span's 10 px vertical padding makes wrapper intersection differ from source exposure; a reader scroll boundary can leave that error observable much longer than the geometric margin suggests.

The repair measures the registered quote's actual content Range rectangles rather than wrapper padding. Every nonempty source rectangle must fit the viewport and clipping ancestors, retain visible layout/opacity, and hit the rendered source. DOM source registration and exact raw progress remain authoritative; independent collector/scoring code remains unchanged. IntersectionObserver only requests measurement. Scroll, resize, document visibility and root ResizeObserver events request one owned animation frame; teardown removes listeners/observers and cancels pending work. Fully offscreen and partial multiline quotes remain ineligible until complete geometry enters. Explicit held inspection is still accessible and wins after the source moves offscreen.

Node geometry fixtures supplement a real browser regression asserting actual renderer state and an exact Queen cup automatic exposure of at least 600 ms after full entry. Existing held/deadline, duplicate/reconnect, source replacement, reduced/restored, hidden-frame and teardown controls remain part of the bounded verification. Runtime identity includes enumerated actual source/shared/font file hashes; enclosing Git HEAD is provenance only.

## Visibility rule: alignment prototyped, not adopted

A prototype (v4 of this revision) relaxed the renderer to the independent collector's definition: each quoted source fragment needed one unclipped line whose clipped center hit-tests to its text. Its two strict five-card runs passed 25/25 and its Star run 6/6, but those runs happened to have no late frame gaps, so they do not show it would survive them; and it changed when highlights start: a connection could begin when only its first line, even a one-pixel sliver, peeked in at the bottom edge, before the reader could read it. The reviewed rule above only delays such a connection until its whole quote is in view, so it is not skipped while the quote fits the unobstructed reading area. A quote taller than that area (for example under the sticky phone companion or at 200% zoom in landscape) never becomes eligible and is consumed unplayed once it passes above the viewport; that limit predates this revision and is recorded, not changed. The prototype also depended on probe-only leaf spans, so production would have used a different rule from the one qualified. Because that is a product change made to satisfy a conservative measurement, it is withdrawn here and the complete-geometry rule stays. The v4 patch and its evidence remain available if the owner prefers the earlier start.

The strict controls' residual sensitivity comes from the measurement's first-interval rule combined with frame gaps. While the renderer waits for complete geometry, a frame gap over 100 ms ends the collector's first visible interval, and the later full turn no longer counts. The v3 miss was this case: `tone-check-return` straddled the bottom edge from 238.4 s, the collector's first interval ended on a 103 ms gap at 251.8 s, and the connection then took its full 1.7 s turn at 260.2 s.

Diagnosed source of the deterministic five-card stalls (148–221 ms, about 28–35 s into the paced session, while the "Putting It Together" section streams): raster work, not script. During each stall all four Chromium raster threads were busy for the whole interval while the main thread did 3–13 ms of animation-frame work and waited to commit. 3.7 s of the 4.2 s raster time in the traced 8 s belonged to one layer, the prose container's decorative `.narrative-atmosphere::after` wash (eight full-size radial gradients and a mask, 578 × about 3,000 px), composited separately because it overlaps the animated dust `::before`. Every streamed delta that grows the prose re-rasters it. In-page ablation (diagnostic stylesheet only, no source edits): hiding `::after` removed every stall; hiding or freezing the dust `::before` left two; removing the mask, disabling the beat bloom, or interpolating in sRGB left five. The atmosphere predates this work (January and September 2026) and is unchanged; making it cheaper is a design decision for the owner. The traces and ablation runs are in the remediation workspace (`frame-gap-diagnosis/run5`–`run8`).

## Fallback-first introductions: open decision

Before a visual job's ledger arrives, the page's fallback passage registry can give a visible card identity its own automatic turn. When the ledger arrives with an identity for the same passage and card under a new id, that identity takes its own turn as well, so the same introduction can show twice (immediately when the ledger arrives mid-turn, or later if it arrives after the first turn ended). The strict production-scheduler lanes rarely show it because their ledger arrives within about 30 ms; with real model latency the fallback-first path is normal.

The frozen scorer credits only an exposure of the ledger cue itself, adopted after its receipt. Carrying the fallback play over to the ledger successor would therefore record that introduction as never shown whenever the ledger is slower than the fallback turn. The remedy compatible with both the no-repeat goal and the scorer is to give fallback associations no automatic turns while a visual job is pending (they stay available for explicit revisit), and to restore them when no job exists or the job fails. That changes production timing, since highlights would wait for the ledger, so it is left for the owner to decide. The late-visible browser test reports fallback turns as an annotation instead of hiding them.

## Verification and limits

Reducer regressions cover co-arriving turns in source order, deadlines preserved while later connections wait, held release resuming the earliest unplayed connection, passed versus below-view waiting connections, reduced-motion static turns, mid-turn motion-preference changes, suspension and resumption across modal/card-detail/stage-focus inspection and a hidden document, status carried by a source update, paused or errored readings never adopting, a turn ending with its passage and leaving no stale wait, an inspection after a turn has ended, holding during a suspended turn, new turns never inheriting a suspension, and unchanged restored behavior. A mutation probe of 17 plausible wrong reducers is fully caught by these tests; the independent reviewer's own 18-variant probe caught 17, with the survivor judged effectively harmless. The provider's wakeup choice is the exported pure `nextGestureDeadline`, unit-tested directly. Four earlier tests encoded only the rejected latest-only rule and were replaced; three others were edited to match the decided contract: the completed-live-cue and visibility/status tests now isolate a single visible connection, and the reduced-motion modal test expects a waiting static turn rather than no pending connection.

Browser specs changed with the contract. Burst and final-only Star sessions now require every connection to be shown, instead of asserting the old skipping as an accepted limitation. The late-visible test requires one automatic turn per visible connection in source order. Stage-sequence recorders replace "latest cue replaces backlog". The stage-focus browser test reaches the card with the keyboard and checks `:focus-visible`; a second test clicks to hold and release the stage card and requires later turns to continue without clicking elsewhere. The five-card full-phase ideal-arrival control is an explicit offline diagnostic: its schedule exceeds the 10 s receipt-lag gate by construction, so it asserts that rejection while still requiring every expected exposure; the production-scheduler five-card control remains the strict positive. Task 2's note that both strict positives retain every failed assertion described the pre-decision policy and is superseded here.

Qualification runs record no Playwright trace: on the same offline five-card session, trace recording during frame-polled waits produced 9 unobserved >100 ms frames per 60 s versus 0 without it, and those gaps ended first visible intervals before later turns. Gap detection, thresholds, scorer and clocks are unchanged. The streaming stalls that remain with trace off are the decorative raster cost described above, not the in-page collector.

Browser results for each revision are recorded in the Task 3 report with their evidence; this document states the contract, not a qualification result. These are offline fixture controls: they do not establish live model semantics, real Pro authentication, physical devices or production behavior. This record authorizes no provider calls, release, migration or production access.
