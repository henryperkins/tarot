# AI configuration dashboard remediation plan

Type: plan
Status: closed
Last reviewed: 2026-11-19

The local audit exercised all seven feature editors against a Worker and D1. Ordinary saves, fallback reordering, sample reruns, history filters and pagination worked. The remaining defects affect what an admin can safely save, recover, verify and reach. The desktop acceptance case remains **High saved → Medium tested → Low draft** for OpenAI Readings. [Dashboard contract](../specs/2026-11-19-ai-configuration-dashboard-design.md) · [Visual reference](../../reference/ai-configuration-dashboard-concept.jpg)

Start with tasks 1 and 2 in parallel. Task 3 builds on the stored-policy handling in task 2. Tasks 4–7 can proceed independently once their API fields are agreed. Add the failing regression for each finding before changing its behavior.

## 1. Make saving and leaving unambiguous

- [x] Track the saved baseline, submitted snapshot and current draft independently. While a save is pending, keep the editor open on attempts to change feature, leave via the rail, sign out or navigate Back. Announce “Saving changes to Readings…” using the actual feature name. Keep ordinary editing and sibling tabs available. After acknowledgement, compare the latest draft against the acknowledged settings. On failure retain the draft and support retry with the same mutation ID for an identical submission. [Editor](../../../src/pages/AdminAiConfiguration.jsx) · [Draft helpers](../../../src/lib/adminAiConfiguration.js)
- [x] For a dirty draft with no pending save, make one decision govern departure. **Keep editing** retains the draft. **Discard changes** proceeds to the captured destination and suppresses the native unload prompt for that confirmed exit only. Capture the Back destination before releasing the guard’s temporary history entry. An ordinary dirty reload or window close still uses the browser prompt. [Back guard](../../../src/hooks/useAndroidBackGuard.js)
- **Acceptance.** Delay the write before it reaches D1, then repeat with the write committed and its response held. Try feature switch, rail, sign-out and Back in both windows. No action offers to discard a submitted write. Submit Medium, change to Low or back to the original High while saving, then release the response. Medium is saved once and the newer choice is still editable. Cover failure, lost-response retry, conflict and tab return. Exercise browser Back to both an app route and a previous full document. Confirming discard reaches the intended destination with one prompt.

## 2. Recover one retired model without losing the dashboard

- [x] Separate reading a saved revision for display from validating a policy for execution or save. If a model is no longer in the deployment catalog, return the affected feature, revision, current concurrency token, saved identifiers and affected slots. The other six editors, connections and history must open. Distinguish this case from a database outage, a feature with no revisions and an unreadable schema version. [Store](../../../functions/lib/aiConfigStore.js) · [Admin API](../../../functions/api/admin/ai-configuration.js) · [Catalog](../../../functions/lib/aiConfigCatalog.js)
- [x] Give the admin a repair path for a retired primary **or fallback**. Show the saved identifier, offer a supported replacement for each affected slot, preserve valid settings and order, and preview the diff. Saving appends a normal revision using the current base token. Keep an unresolved assignment’s existing runtime failure handling and mandatory safeguards. Jobs already admitted retain their snapshot. An unknown schema version gets an isolated migration-required state, with its historical row preserved.
- **Acceptance.** Save a valid assignment using a custom deployment model, rotate the deployment model, and reopen the dashboard. Test both primary and fallback retirement. Repair, reload and run a new request with the replacement. Check that the original revision is intact, a competing repair conflicts and an identical retry creates one revision. Exercise a genuine D1 error separately. [Worker fixture](../../../tests/helpers/aiConfigWorker.mjs) · [Reading admission](../../../functions/lib/readingConfigPolicy.js)

## 3. Align Workers AI reasoning choices with effective behavior

- [x] For GLM-5.3 and Flash, expose **Task default**, **Low**, **High** and **Max** in Guided coach, Coach action extraction, Reading evaluation and Quality gate. Enforce the same explicit choices on new writes and samples. Cloudflare maps Medium to Max for both models. Keep the OpenAI Readings Medium case in the regression suite. [GLM-5.3](https://developers.cloudflare.com/workers-ai/models/glm-5.3/) · [GLM-5.3 Flash](https://developers.cloudflare.com/workers-ai/models/glm-5.3-flash/)
- [x] Resolve previously saved GLM aliases and inherited deployment values to their documented effective level for comparison, runtime and sample display. For an existing Medium revision show “Saved as Medium · effective Max.” Opening it must leave the editor clean. Keep raw history and retry receipts interpretable. Account for old catalog versions and mutation digests when validating retries of acknowledged writes. [Catalog](../../../functions/lib/aiConfigCatalog.js) · [Task policy](../../../functions/lib/textFeaturePolicy.js)
- **Acceptance.** Seed the old Medium value in D1 and in a deployment default. Assert the displayed level, actual adapter payload, historical value and absence of a new revision on load. Submit an unsupported new value directly to the API. Test both GLM models and all four editors.

## 4. Attribute sample text to the call that delivered it

- [x] Capture generation and repair separately at the adapter boundary. Carry provider, fallback position, reported or configured model, and actual effort through the buffered follow-up delivery decision. Render the source of the displayed excerpt. Keep the requested draft and its freshness independent of the delivered call. Safety replacements identify the safety outcome. For older short-lived receipts lacking repair details, show only what was recorded. [Follow-up delivery](../../../functions/api/reading-followup.js) · [Sample runner](../../../functions/lib/aiFeatureSamples.js) · [Result panel](../../../src/components/admin/FeatureSample.jsx)
- **Acceptance.** Use a two-response stub. Generate a High-effort answer that names an extra card, then repair it at Low with a distinct reported model ID. Assert both outbound requests and that the displayed excerpt, model and effort belong to the repair. Cover a clean initial answer, repair after a fallback, an unsuccessful repair, safety replacement and a missing reported model. A later draft edit still marks the receipt as earlier.

## 5. Restore keyboard access, short-screen controls and credential masking

- [x] Make **Skip to main content** focus the current main region in the sign-in, loading and editor states. When a keyboard user selects a foreground or background feature, land focus on the new editor heading or selected row. On a canceled mobile navigation attempt, return focus to the visible initiating link or menu button. [Skip link](../../../src/components/SkipLink.jsx) · [Admin shell](../../../src/components/admin/AdminShell.jsx)
- [x] Let a tall save summary or conflict message flow with the page when the viewport is too short for a sticky footer. Preserve the desktop save bar. Reset key visibility when the admin signs out or the session expires. [Dashboard styles](../../../src/styles/admin-configuration.css) · [Admin authentication](../../../src/components/admin/AdminAuthGate.jsx)
- **Acceptance.** Check actual focus and the next Tab destination after skip, feature selection and **Keep editing** or Escape in mobile navigation. With a multi-field diff and then a conflict, exercise the fields, reorder buttons, **Run sample**, **Discard** and **Save** at 320 × 380 and 320 × 256 CSS pixels with ordinary pointer clicks and the keyboard. Verify focused controls are visible and clear of the footer. Repeat the reference desktop state at 1280 × 853. Reveal the key, sign in, then sign out or expire the session. The next form has an empty password field and a **Show key** control.

## 6. Explain sample availability, specialist readiness and the Quality gate

- [x] Supply a safe reason beside a disabled sample action when sample storage is missing or an environment policy restricts sampling. Distinguish that from a runnable fixture that can legitimately fall back or return a failure. [Admin API](../../../functions/api/admin/ai-configuration.js) · [Sample panel](../../../src/components/admin/FeatureSample.jsx)
- [x] Use the runtime’s `getPersonalTextProvider` parser for dashboard writability and release-settings availability. The runtime trims and normalizes `TEXT_PROVIDER`. With the value `' Legacy '`, the dashboard currently denies editing and reports owner mode even though public routing is active. For an invalid value, explain the configuration error on affected assignments and keep unrelated editors usable. [Provider selection](../../../functions/lib/personalTextProvider.js)
- [x] Derive specialist status from the same checks the runtime uses. Reuse visual cue and embedding readiness and share the narration provider checks with the TTS endpoint. Distinguish the configured model from its availability. Expose only safe status and model metadata. Keep the specialist inventory, provider connections and single-environment label informational. [Specialist inventory](../../../functions/lib/aiConfigCatalog.js) · [Visual cues](../../../functions/lib/visualCueProvider.js) · [Embeddings](../../../functions/lib/embeddings.js) · [Narration](../../../functions/api/tts.js)
- [x] In **Quality gate**, display whether grading is enabled, when the gate runs, what happens when the grader is unavailable, and when restricted inputs or unsupported languages require a closed gate. Derive this read-only description from the delivery policy and its environment defaults. [Selective gate policy](../../../functions/lib/evalGatePolicy.js) · [Grading and failure modes](../../../functions/lib/evaluation.js)
- **Acceptance.** Remove the sample binding and read the reason on screen. Compare public routing, normalized mixed-case/whitespace values, both owner providers and an invalid value across the catalog, samples and release endpoint with their existing environment restrictions. Check inventory against runtime readiness for a valid configuration, an invalid visual-cue effort, whitespace-only ElevenLabs credentials and a Workers AI binding without a callable `run`. Compare the gate description with actual delivery decisions for global, selective and grading-disabled configurations, including ordinary and mandatory checks with an unavailable grader.

## 7. Make history readable across changes and environments

- [x] Render an order change as two labeled ordered lists, **Before** and **After**. Identify the environment, revision, actor and explicitly labeled UTC timestamp on each entry. Preserve readable names for retired models and the recorded values of historical settings. [History view](../../../src/components/admin/ConfigurationRecords.jsx) · [History query](../../../functions/lib/aiConfigStore.js)
- **Acceptance.** Change a primary provider that swaps the fallback order. Read each complete order independently. Seed more than 25 matching changes interleaved with other features. Exercise **Load more**, all seven filters, switching filters after paging, empty results and retry. Verify no duplicates or omissions and that the UTC time is identical in browsers set to different time zones.
