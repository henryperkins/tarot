# Coach refinement meaning preservation

The user authorized the bounded follow-up proposed after the live coach release: harden AI refinement, regress the captured sister/timing failure, and validate six fixed live cases while preserving unrelated work. Commit, push and deployment are outside this follow-up.

Existing-question refinement becomes a minimal editing task using the current question and optional explicit detail. Default topic/timeframe/depth, spread structure, journal recommendations and astrology do not enter that model request, and no ephemeris forecast is fetched. Fresh generation retains its existing behavior. Clear questions may be returned unchanged; the original language, people, concern, negation and literal explicit timing must survive.

Prompt-only instructions were insufficient in the captured live case. The implementation therefore combines a narrow prompt with conservative deterministic acceptance checks. A second model judge would add cost and another uncertain judgment; it is not part of this change. Timing checks protect only confidently recognized literal spans, without assuming Latin script means English. A conservative content check rejects unsupported additions, dropped concrete anchors, changed people/negation, and excessive expansion. Generic grammatical/framing edits and a small set of source-activated equivalences are allowed. These are constraints, not a semantic quality score. Unknown useful paraphrases may be preserved as the original instead of accepted; comprehensive preservation of meaning is not claimed.

Rejected suggestions return the exact original with `local-preserved`, no model/forecast in the public result, and truthful internal rejected-attempt metadata. Daily feature usage is released; actual provider usage remains recorded. UI fallback copy says wording was kept, without implying a provider outage when a constraint caused preservation.

The captured bad answer is retained as regression data. Checks cover exact relative/calendar timing, names/relationships, negation, invented silence, supported silence, unchanged questions, Spanish, valid narrow edits, fallback/accounting, and fresh-generation parity. Six live cases run once each in fixed order using the candidate prompt, actual configured Workers AI model/settings and candidate acceptance guard. Raw output and delivered output are recorded separately, with source/prompt identity and editorial review. No production app deployment or real-user content is used.
